# SP6d — Mail Sentinel: Trust surface + write-path residuals — Design (draft)

- **Status:** Draft
- **Date:** 2026-08-12
- **Predecessor:** SP6c (Early Spam Filter) — see
  `2026-08-10-sp6c-early-spam-filter-design.md`
- **Author:** overnight polish loop (Claude Opus 4.7)
- **Scope:** collect residuals from SP6c UAT that were deferred for
  safety, plus the next thin layer of operator trust surface (Rules
  CRUD in UI, Origin mailbox on Recent Spam, better SSE cleanup).

## Motivation

SP6c reached prod-ready for the classifier itself — buckets fire
correctly, spam actually moves to Indésirables, decisions row keeps
an audit trail. But two classes of gap remain:

1. **Operator trust surface still requires SSH.** Rules can only be
   inspected via the CLI or edited via the API. The Rules tab shows
   priority + enabled state but is read-only. When a legitimate mail
   was misclassified during UAT, the fix path was
   `psql -c "UPDATE mail_sentinel_rule …"`.
2. **A handful of correctness residuals were parked** during the
   overnight polish because their fixes touched non-touchable
   infra: SSE broker thread leak, the daemon
   `AWAITING_USER → DONE` illegal-transition fallthrough, and the
   schema addition for Origin mailbox on `mail_sentinel_spam_decision`.

SP6d closes both.

## In scope

### A. Rules CRUD in UI (Propose / Apply flow)

- Rules tab gains a "New rule" button and per-row "Edit" affordance.
- Form fields: name, description, priority, enabled toggle, JSON
  editor for condition, checkbox picker for actions
  (archive / mark_read / label:<slug> / notify:<channel>).
- **Propose step:** on submit, POST to `/mail-sentinel/rules/propose`
  which:
  - Validates the JSON against the same schema `rules_store.create`
    uses today.
  - Simulates the rule against the last 200 spam decisions
    (dry-run: recomputes rule matches without writing) and returns
    `{matched: [decision_id, …], would_shadow: [rule_name, …]}`.
- The UI shows the simulation output; operator clicks Apply to
  commit via POST `/mail-sentinel/rules` (existing endpoint).
- **Why Propose / Apply, not straight PATCH:** Rules are the
  sharpest lever in the pipeline (see ADR
  `2026-08-12-sp6c-uat-learnings.md` §2). A raw editor invites
  test-drive edits that shadow the seeded ops rules.

### B. Origin mailbox column on Recent Spam tab

- Schema: `sql/013_add_origin_mailbox.sh` — adds
  `origin_mailbox_id TEXT` and `origin_mailbox_role TEXT` (nullable)
  to `mail_sentinel_spam_decision`. Idempotent (
  `ALTER TABLE … ADD COLUMN IF NOT EXISTS`).
- Adapter: `_terminate` node in
  `src/twaky/sentinels/mail/nodes.py` captures the mail's first
  mailboxId + resolves its role BEFORE the atomic Junk move, passes
  both into `record_spam_decision(...)`.
- API: extend `GET /mail-sentinel/spam/recent` row shape with
  `origin_mailbox_role` (opt-in via `?with_origin=1` for backward
  compat during rollout).
- UI: new column between "Received" and "Signal" showing the role
  (`inbox`, `newsletter`, `archive`, or a truncated UUID if role
  unresolved).

### C. SSE broker cleanup (flake #4 root cause)

- Root cause parked in
  `docs/superpowers/investigations/2026-08-10-nine-flakes.md`:
  `SSEBroker.stop` cancels its listen task, but the underlying
  psycopg LISTEN generator opens an executor-owned thread that
  outlives the cancel — the test hangs at teardown.
- Fix: switch `SSEBroker` to `psycopg.AsyncConnection` with an
  explicit `close()` in `stop`; add a `join(timeout=5)` on the
  executor thread as a safety net.
- Restores `tests/integration/test_api_sse.py::…end_to_end` to a
  live-runnable state (currently skips-on-unreachable but hangs
  when reachable + owner_email matches).

### D. Daemon AWAITING_USER fallthrough

- Root cause: `_run_mission_sync`'s tail calls
  `engine.finish(mid, "done")` when no finish marker AND no pending
  input surfaced. From `AWAITING_USER`, that's an illegal
  transition per the state machine's `_ALLOWED[AWAITING_USER] =
  {RUNNING, CANCELLED, FAILED}` mapping.
- Fix: guard the fallthrough on `mission.state != AWAITING_USER`
  — for a mission that came in via resume and returned without a
  new pending, the correct action is to leave it in AWAITING_USER
  (the graph acknowledged but didn't advance).
- Reverts the test-side workaround from flake #8 (the fake graph
  can stop stubbing `engine.finish`).

### E. Live-JMAP integration tests

- Add a live-mode marker `@pytest.mark.jmap_live` that runs the
  `test_mail_roundtrip.py` and `test_spam_triage_end_to_end.py`
  paths against a real JMAP account when `TWAKY_JMAP_LIVE=1`.
- Fixture provisions a throwaway test folder in the account so
  UAT-style regressions are catchable in CI without permanent
  side-effects on the operator's inbox.

### F. Multi-worker circuit breaker (opt-in)

- Today `LLMCircuitBreaker` is process-local. Multi-worker sentinel
  fleets would each open their own breaker on the same upstream.
- Add a Postgres-backed variant `LLMCircuitBreakerPg` gated behind
  `SENTINEL_BREAKER_MODE=pg` — shared failure counter via
  `INSERT ON CONFLICT UPDATE` on a small `llm_circuit` table.
- Local mode remains the default; PG mode is opt-in for the day we
  scale out.

## Out of scope (SP6e or later)

- Full rules editor with visual condition builder (JSON is enough
  for SP6d; operators willing to edit JSON are the target audience).
- Origin mailbox backfill for pre-SP6d decisions — new column
  starts NULL for historical rows, filled forward-only.
- Multi-tenant rule namespaces (rules are per-owner today via the
  daemon's owner filter; no cross-owner sharing planned).

## Success criteria

- Operator can create + edit + delete a rule from the UI without
  hitting a terminal.
- Recent Spam tab shows origin mailbox for every decision written
  after SP6d ships.
- Full test suite green, including the previously flaky
  `test_sse_delivers_mission_changed_end_to_end` and
  `test_awaiting_user_mission_takes_resume_branch` (with the
  test-side workaround removed).
- Overnight `TWAKY_JMAP_LIVE=1` cron passes for one week on the
  primary owner's account with no false positives against
  legitimate mail.

## Risks

- The Propose step's simulation is only as good as the last 200
  decisions — a rule that shadows a legitimate email older than
  that window will not surface. Mitigation: allow the operator to
  scope the simulation window via URL param.
- Live-JMAP CI will leak throwaway folders if the fixture crashes
  mid-run. Mitigation: nightly cleanup job matching a
  `zzz-twaky-test-*` prefix.

## Open questions

- Should the Propose step also predict the effect on the
  classifier's LLM budget? (rules that short-circuit spare LLM
  tokens — a real operator would want to see the projected
  savings). Probably yes, deferred to SP6e.
- Does the Origin mailbox column need to be searchable? Filtering
  the Recent Spam tab by origin would help debug "why did this
  newsletter get classified as spam" flows. Probably yes, but the
  schema is the same either way.
