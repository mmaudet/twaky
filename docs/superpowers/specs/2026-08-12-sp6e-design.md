## In scope

### A. SSE broker cleanup — fix flake #4 root cause

**Symptom:** `test_sse_delivers_mission_changed_end_to_end` hangs
at teardown when Postgres is reachable. Root cause: the
`SSEBroker._listener` uses `twaky.daemon.notify.listen`, which
runs a blocking `psycopg` connection in a thread via
`loop.run_in_executor`. When the listener asyncio task is
cancelled by `SSEBroker.stop()`, the executor thread is NOT
joined — psycopg is stuck in `conn.notifies(timeout=None)` and
the thread outlives the test.

**Fix:**

Change `twaky.daemon.notify.listen` to accept a `stop_event:
asyncio.Event | None = None`. Inside `_run`, replace the
infinite `for note in conn.notifies(timeout=None)` with a loop
that polls with a bounded timeout (e.g. 0.5s) and exits when
`stop_event.is_set()`. The listener task can then cancel via
setting the event; the executor thread returns cleanly.

Additionally: `SSEBroker.stop()` calls the notify listener's
future with `.result(timeout=2)` after cancelling to ensure the
thread is joined.

**Test:** re-enable
`tests/integration/test_api_sse.py::test_sse_delivers_mission_changed_end_to_end`
without the pre-existing `_broker_thread_leak` xfail; it should
complete within the current 10s timeout.

### B. Daemon `AWAITING_USER → DONE` fallthrough guard

**Symptom:** `_run_mission_sync` at
`src/twaky/daemon/atlas_daemon.py:282-287` calls
`engine.finish(mid, "done")` when the graph returns without a
pending user input AND without a `__ATLAS_FINISH__` marker. From
`AWAITING_USER` state, the state machine's
`_ALLOWED[AWAITING_USER] = {RUNNING, CANCELLED, FAILED}` mapping
rejects this transition, causing an `InvalidTransition`
exception that is logged but leaves the mission stranded.

**Fix:**

Read the current mission state before the fallthrough. If
`state != RUNNING`, log the mismatch (e.g., resume returned
without progress, mission is still AWAITING_USER) and return
without calling `engine.finish`. The mission stays in its
current state; the operator can re-trigger a resume with fresh
input.

**Test:** revert the T1-parking workaround in
`tests/integration/test_daemon_recovery.py::TestRecoveryHandlesAwaitingUser
::test_awaiting_user_mission_takes_resume_branch` — remove the
`engine.finish` stub, remove the `__ATLAS_FINISH__` avoidance,
and assert directly that the mission stays in AWAITING_USER
after the daemon returns.

### C. `@pytest.mark.jmap_live` marker for real-account tests

**Goal:** allow selected integration tests to run against a real
JMAP account when `TWAKY_JMAP_LIVE=1`, self-skip otherwise. This
lets CI catch regressions the mock-based tests miss (JMAP method
argument shape, header casing, mailbox role lookup) without
committing to a permanent live-CI dependency.

**Fix:**

- Register `jmap_live` marker in `pyproject.toml` under
  `[tool.pytest.ini_options.markers]`.
- Add a `pytest.fixture` in `tests/conftest.py` named
  `jmap_live_folder` that, when `TWAKY_JMAP_LIVE=1`:
  - Reads `JMAP_ENDPOINT`, `JMAP_ACCOUNT_ID`, `JMAP_TOKEN` from
    env (fail-fast if any missing).
  - Provisions a throwaway mailbox with prefix `zzz-twaky-test-`
    + a UUID via `Mailbox/set create`.
  - Yields the mailbox id.
  - Cleanup: `Mailbox/set destroy`. If destroy fails
    (network hiccup), leave the folder — the prefix lets a
    manual cleanup script sweep it later.
- Mark
  `tests/integration/test_mail_roundtrip.py::test_send_and_receive_email`
  with `@pytest.mark.jmap_live` and rewrite it to use the fixture
  instead of the current mock-based path.

**No changes to CI config in this spec** — CI already picks up
the marker via pyproject and skips by default. Operators opt in
locally with `TWAKY_JMAP_LIVE=1 uv run pytest -m jmap_live`.
