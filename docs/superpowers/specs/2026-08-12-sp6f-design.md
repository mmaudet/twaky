## Theme

Two threads bundle cleanly under one spec: **sentinel/runtime
hardening** (PG-backed circuit breaker + CI cron for the live
JMAP marker) and **JMAP send path** (unblocks the SP6e demo test
upgrade + several downstream missions). Plus one bonus: kill

The user-facing surface doesn't change. This spec is entirely
operational + infra.

## In scope

### A. PG-backed multi-worker LLM circuit breaker

**Motivation:** SP6c's `LLMCircuitBreaker` (in-process singleton)
is fine at current scale (one sentinel worker) but collapses to
"N workers each open their own breaker" if we scale out. When
the upstream LLM is flapping, all N workers should see the same
break signal.

**Design:**

- New opt-in mode via env: `SENTINEL_BREAKER_MODE=pg` (default
  `local`, preserving today's behaviour).
- New Postgres-backed variant `LLMCircuitBreakerPg` in
  `src/twaky/sentinels/mail/robustness.py`.
- New table `llm_circuit` (single-row-per-model, or per-
  provider — pick the narrower grain):

  ```sql
  CREATE TABLE IF NOT EXISTS llm_circuit (
      key           TEXT PRIMARY KEY,   -- e.g. "mail:default" or a model id
      failure_count INTEGER NOT NULL DEFAULT 0,
      opened_at     TIMESTAMPTZ,        -- NULL when closed
      probe_at      TIMESTAMPTZ,        -- next probe attempt
      updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
  );
  ```

- `LLMCircuitBreakerPg.record_failure()` does
  `INSERT ... ON CONFLICT (key) DO UPDATE SET failure_count =
  failure_count + 1, updated_at = now()` in a single round-trip.
  When `failure_count` crosses the threshold, sets `opened_at`
  and `probe_at`.
- `record_success()` closes the breaker (`opened_at = NULL,
  failure_count = 0`).
- `is_open()` reads the row; if `opened_at IS NOT NULL AND
  probe_at > now()`, open. Cache the result in-process for 5s
  to avoid a query per LLM call.

**Migration:** `sql/014_add_llm_circuit.sh` — idempotent,
non-blocking. NOT executed against live twaky-pg by /goal; the
operator applies it manually.

**Tests:**

- Unit tests on `LLMCircuitBreakerPg` with a fake connection
  pool: threshold trip, cool-off, probe-then-close cycle.
- Integration test (opt-in on `TWAKY_ALLOW_DESTRUCTIVE_TESTS=1`)
  that exercises the DB round-trip.
- Verify the existing `LLMCircuitBreaker` (local) is byte-
  identical when `SENTINEL_BREAKER_MODE` is unset.

### B. CI cron for `@pytest.mark.jmap_live`

**Motivation:** SP6e shipped the marker + fixture but no CI
schedule. Manual soak week is complete (or will be by the time
this ships); wire it up.

**Design:**

- New GitHub Actions workflow `.github/workflows/jmap-live-
  nightly.yml`:
  - `on: schedule: cron: '0 3 * * *'` (nightly at 03:00 UTC).
  - Job runs on `ubuntu-latest`, checks out main, sets up uv +
    Python 3.12.
  - Secrets: `JMAP_ENDPOINT`, `JMAP_ACCOUNT_ID`, `JMAP_TOKEN` —
    stored in GitHub Actions secrets under a dedicated env
    (e.g., `jmap-live`).
  - Runs `TWAKY_JMAP_LIVE=1 uv run pytest -m jmap_live -v
    --tb=short`.
  - On failure: opens an issue in the repo with the pytest
    output attached, tagged `regression:jmap-live`. Uses the
    stock `actions/github-script` for issue creation.

- A weekly cleanup workflow `jmap-live-cleanup.yml` that runs
  `TWAKY_JMAP_LIVE=1 uv run python scripts/sweep_test_folders.py`
  — a small script that lists all mailboxes with the `zzz-twaky-
  test-*` prefix and destroys them (SP6e's fixture leaves them
  on cleanup failure).

**Test:** the workflow itself is validated via
`.github/actions-lint` or `actionlint` in a PR check; no runtime
test.

### C. JmapClient Email/set send path

**Motivation:** SP6e's demo `test_send_receive_roundtrip` had
to fall back to a read-side probe because `JmapClient` has no
send method. This blocks several downstream jobs: real-account
roundtrip validation, the Agent Studio's outbound email tools
(planned SP4), and the ability to programmatically seed test
mailboxes with known content.

**Design:**

- Add `JmapClient.email_send(account_id, envelope) -> str` (the
  server's chosen `id` for the created email).
- The envelope shape follows RFC 8621 §4.1 (Email object):

  ```python
  envelope = {
      "from": [{"email": "...", "name": "..."}],
      "to": [{"email": "...", "name": "..."}],
      "subject": "...",
      "textBody": [{"partId": "1", "type": "text/plain"}],
      "bodyValues": {"1": {"value": "..."}},
      "mailboxIds": {mailbox_id: True},
      # Optional: cc, bcc, headers:<Name>:asText, inReplyTo, references
  }
  ```

- Under the hood: `Email/set create` + `EmailSubmission/set
  create` (RFC 8621 §7). The two-step is required for actual
  delivery; `Email/set` alone just puts a draft in Sent.
- The client returns after the JMAP server acknowledges the
  create, NOT after actual SMTP delivery — deliverability is
  the server's problem.

- Extend `plume.tools.SendEmail` (or the equivalent) to call
  `email_send` when the operator explicitly requests actual
  send (as opposed to `save_draft`). This is a small wiring
  task; the bulk is the client method itself.

**Tests:**

- Unit tests on `email_send` with a mocked httpx client:
  correct method call, correct payload shape, error surfacing.
- Upgrade `tests/integration/test_jmap_roundtrip_live.py`
  (SP6e demo test) to actually send an email to itself, poll
  the target folder for 10s, verify content, cleanup.

### D. Deterministic delegation resolver — kill flake #1 for good

**Motivation:** Baseline PR #8 improved the delegation resolver
from single-shot to polling, but the test still occasionally
flakes under full-suite GIL contention (the polling window can
miss the mission if delegate() blocks for >4s in `engine.
declare` or in `asyncio.run(_await_terminal)` setup).

**Design:**

- Replace polling with an explicit synchronization primitive.
- Instrument `Delegation.delegate()` to accept an OPTIONAL
  `on_declared: Callable[[UUID], None] | None = None` callback,
  invoked exactly once right after `engine.declare` returns
  and BEFORE the LISTEN loop starts.
- Test wires the callback to `threading.Event.set()`, resolver
  thread waits on the event (with a 2s timeout for safety),
  then queries by mission_id (no more list_all scan).
- The callback is opt-in (default None); production code paths
  don't use it, no runtime cost.

**Tests:**

- Update `tests/sentinels/test_delegation.py::
  test_delegate_returns_done_when_mission_completes` to use
  the callback.
- Add `test_on_declared_callback_fires_exactly_once` — assert
  callback invoked with the correct mission id before delegate
  returns.

### E. `sweep_test_folders.py` script (feeds B's cleanup workflow)

**Design:**

- New file `scripts/sweep_test_folders.py`.
- Reads `JMAP_ENDPOINT`, `JMAP_ACCOUNT_ID`, `JMAP_TOKEN` from
  env (fail-fast if missing).
- `Mailbox/query` for `parentId == None AND name startsWith
  "zzz-twaky-test-"`.
- For each match, `Mailbox/set destroy`.
- Logs one line per destroyed folder + a final tally.
- Exit code 0 on success (including zero matches), 1 on any
  destroy failure.

**Test:** unit test with a mocked httpx client — the script's
composition + response parsing. No live test (the
`jmap-live-cleanup.yml` workflow itself exercises the live
path).

## Success criteria

1. `SENTINEL_BREAKER_MODE=pg` sentinel processes events with a
   PG-backed breaker; when the LLM upstream flaps, all workers
   share the open state (verified via a dual-worker integration
   test).
2. `jmap-live-nightly.yml` runs on a schedule, opens an issue
   on failure, closes it automatically on the next green run.
3. `sweep_test_folders.py` script + `jmap-live-cleanup.yml`
   workflow keep the throwaway JMAP account clean of stale
   `zzz-twaky-test-*` folders (weekly sweep).
4. `JmapClient.email_send` sends a real email against the
   Linagora tmail account (via the SP6e demo test upgrade),
   the mail arrives in the target folder within 10s.
5. `test_delegate_returns_done_when_mission_completes` passes
   100 consecutive full-suite runs (previously flaked ~10%).
6. Full non-integration suite baseline: 0 fails (post-PR #8
   merged, this closes the residual delegation flake).

## Risks

- **PG breaker adds a round-trip per LLM call.** Mitigation:
  5s in-process cache. If the LLM call latency dominates, this
  is noise. If we hit a hot path with sub-second LLM calls,
  revisit.
- **CI cron secrets management.** `JMAP_TOKEN` in GitHub
  secrets is a bearer token; rotate quarterly. Add a reminder
  to the ADR generated at the end of SP6f.
- **`email_send` deliverability** depends on the JMAP server's
  SMTP relay. If the server rejects (rate-limit,
  quota), the client surfaces the error; the test doesn't
  distinguish "server accepted, upstream refused" from "client
  bug". Acceptable — deliverability tracking is out of scope.
